# Deploying CampusConnect

The app ships as a **single deployable unit**: the Express API serves the built React app, so one web service = one live link. The included `render.yaml` blueprint makes Render deployment nearly one click.

> **Why Render?** Free tier includes Node web services with zero sleep configuration needed for a demo. Trade-off: the service sleeps after ~15 min idle; the first request after that takes ~50 s to cold-start. Perfect for a portfolio, not for production traffic.

---

## 1. MongoDB Atlas (free database)

The deployed app can't use your local MongoDB — create a free cloud cluster:

1. Go to [mongodb.com/cloud/atlas](https://www.mongodb.com/cloud/atlas) → sign up (free M0 tier, no card).
2. Create a **free M0 cluster** (default region is fine).
3. **Database Access** → *Add New Database User* → username + password (choose password auth; note them down).
4. **Network Access** → *Add IP Address* → **Allow access from anywhere** (`0.0.0.0/0`) — required since Render's IPs are dynamic.
5. **Database → Connect → Drivers** → copy the connection string:
   `mongodb+srv://<user>:<password>@cluster0.xxxxx.mongodb.net/?retryWrites=...`
6. Add the database name before the `?`: `...mongodb.net/campusconnect?retryWrites=...`

## 2. Deploy to Render (one link)

1. Go to [render.com](https://render.com) → **Sign in with GitHub** (authorizes access to `shyam050/campusconnect`).
2. Dashboard → **New +** → **Blueprint** → select the `campusconnect` repo.
   Render reads `render.yaml` and pre-fills everything: build command, start command, health check (`/health`), and auto-generated JWT secrets.
3. When prompted for the `MONGODB_URI` variable, paste the Atlas connection string from step 1.6.
4. **Apply** → first build takes ~5 minutes (install → tsc → vite build).
5. Your live link appears at the top: `https://campusconnect-xxxx.onrender.com`
6. After the first deploy: **Environment** → add `FRONTEND_URL` = your onrender URL (used in reminder-email links) → *Save* (this triggers a redeploy).

## 3. Seed the production database

From the project root on your machine:

```bash
MONGODB_URI="mongodb+srv://<user>:<password>@cluster0.xxxxx.mongodb.net/campusconnect?retryWrites=true" npm run seed
```

Then open your Render link and log in with the demo accounts (`admin@campus.edu` / `Admin@123`, etc.).

## 4. Every push auto-deploys

Render is connected to the repo — `git push` to `main` triggers a fresh build and deploy automatically.

## Notes for the live demo

- **Emails**: without SMTP credentials, reminder/status emails are logged to the Render console instead of sent (dev mode). To send real email, add these env vars in the Render dashboard (any SMTP provider works — Gmail with an app password, Resend, Brevo):
  `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `EMAIL_FROM`.
- **Redis / Bull**: unset on Render, so the queue runs in direct mode (same behavior, no Redis bill).
- **Resume uploads**: without Cloudinary credentials, resumes are stored on the Render instance's disk. Fine for demoing — note free-tier disks are ephemeral (uploads vanish on redeploy). Add `CLOUDINARY_CLOUD_NAME` / `CLOUDINARY_API_KEY` / `CLOUDINARY_API_SECRET` for persistent CDN-backed storage.
- **Secrets**: `ACCESS_SECRET` / `REFRESH_SECRET` are auto-generated by the blueprint — never commit real secrets.

## Alternative: split deployment

Want the frontend and API as separate links (e.g., Vercel + Render)? The code supports it — deploy `client/` to Vercel (set `VITE_API_URL=https://<api-url>/api/v1`) and `server/` to Render (set `CLIENT_ORIGIN=https://<vercel-url>`). The single-service blueprint above is simpler and avoids CORS entirely, so start there.
